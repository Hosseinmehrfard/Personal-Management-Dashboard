# مرکز | Personal Management Dashboard

**داشبورد شخصی، فارسی و راست‌به‌چپ برای مدیریت سرورها، وظایف روزانه، امور مالی و مطالعهٔ امنیت وب.**

نسخهٔ فعلی کد: **5.2.0-nerkhara-connector** · React + PostgreSQL · نصب‌شونده به‌صورت PWA · قابل استقرار با Docker Compose

> **وضعیت پروژه:** در حال توسعه و آزمایش. آزمون‌های محلی کد انجام شده‌اند، اما استقرار روی VPS واقعی، ممیزی کامل وابستگی‌ها و آزمون نفوذ مستقل هنوز نهایی نشده‌اند. این نرم‌افزار را بدون بررسی تنظیمات امنیتی روی اینترنت عمومی منتشر نکنید.

## امکانات

| بخش | قابلیت‌ها |
| --- | --- |
| داشبورد مرکزی | پیشرفت کارها، فعالیت‌های اخیر، موارد نیازمند بررسی و خلاصهٔ وضعیت |
| مدیریت سرورها | ثبت سرور، نمایش CPU، RAM و دیسک، ورود دستی یا دریافت معیارها از عامل پایش مجاز |
| وظایف روزانه | ثبت و ویرایش وظیفه، وضعیت، اولویت، موعد و یادداشت |
| مالی | درآمد و هزینه به **تومان**، اقساط، پرداخت‌ها و گزارش‌های ماهانه |
| پس‌انداز و ارز | تعریف ارز/دارایی سفارشی، کد و نماد، مقدار، نرخ هر واحد به تومان و ارزش روز سبد |
| نرخ‌های آنلاین | اتصال رایگان نرخ‌آرا بدون کلید + حفظ API ارزدیجیتال و نوسان، تبدیل نرخ‌ها به تومان، نرخ دستی |
| یادگیری OWASP | فصل‌های OWASP Top 10:2025، مباحث، منابع، یادداشت‌ها، وضعیت صحت‌سنجی و کارهای باز |
| مدیریت | ایجاد حساب مدیر در اولین ورود، تنظیمات API، امنیت حساب و پشتیبان‌گیری |

دسترسی به داده‌ها از طریق Backend انجام می‌شود و رکوردهای اصلی در **PostgreSQL** ذخیره می‌شوند. حالت PWA امکان نصب ظاهر برنامه روی موبایل/رایانه را فراهم می‌کند؛ عملیات وابسته به API و دیتابیس در حالت آفلاین کار نخواهند کرد.

## پشتهٔ فنی

- **Frontend:** React 19، Vite 6 و CSS راست‌به‌چپ
- **Backend:** Node.js 22 و Express
- **Database:** PostgreSQL 17
- **Deployment:** Docker Compose، Caddy و HTTPS خودکار هنگام استفاده از دامنهٔ معتبر
- **PWA:** Web App Manifest و Service Worker
- **Security controls:** راه‌اندازی اولیه با کد اختصاصی، نشست مدیر، محافظت CSRF، هش گذرواژه با `scrypt`، رمزگذاری کلیدهای API و بررسی ورودی‌ها

## نصب روی Ubuntu / Debian

### پیش‌نیازها

- سرور Ubuntu یا Debian با دسترسی `sudo` و ارتباط اینترنتی
- برای دسترسی عمومی امن: **دامنه‌ای که DNS آن به IP سرور اشاره کند**
- پورت **80/TCP** و **443/TCP** (و در صورت استفادهٔ Caddy از HTTP/3، **443/UDP**) در دسترس باشند
- پیش از اجرای نصب‌کنندهٔ اینترنتی، محتوای [`install.sh`](./install.sh) را بررسی کنید

### نصب تک‌دستوری با دامنه

`YOUR_DOMAIN` را با دامنهٔ واقعی خود، مانند `panel.example.com`، جایگزین کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/Hosseinmehrfard/Personal-Management-Dashboard/main/install.sh | sudo bash -s -- https://github.com/Hosseinmehrfard/Personal-Management-Dashboard.git YOUR_DOMAIN
```

نصب‌کننده کد پروژه را در `/opt/markaz` دریافت می‌کند، Docker را در صورت نیاز نصب می‌کند، فایل محرمانهٔ `.env` را می‌سازد و سرویس‌های برنامه، PostgreSQL و HTTPS را راه‌اندازی می‌کند. پس از موفقیت نصب، برنامه از `https://YOUR_DOMAIN` در دسترس خواهد بود.

**نکتهٔ امنیتی:** اجرای `curl | sudo bash` به اسکریپت مخزن دسترسی ریشه می‌دهد. برای نصب کنترل‌شده‌تر، ابتدا مخزن و اسکریپت را بررسی و سپس `install.sh` را از نسخهٔ مشخصی که به آن اعتماد دارید اجرا کنید.

### نصب بدون دامنه (فقط دسترسی محلی)

```bash
curl -fsSL https://raw.githubusercontent.com/Hosseinmehrfard/Personal-Management-Dashboard/main/install.sh | sudo bash -s -- https://github.com/Hosseinmehrfard/Personal-Management-Dashboard.git
```

در این حالت برنامه فقط روی `127.0.0.1:4173` سرور گوش می‌دهد. برای دسترسی از رایانهٔ خود یک تونل SSH باز کنید:

```bash
ssh -L 4173:127.0.0.1:4173 USER@SERVER_IP
```

سپس در مرورگر همان رایانه `http://127.0.0.1:4173` را باز کنید. این حالت **عمومی نیست** و نباید با بازکردن پورت برنامه برای تمام اینترنت جایگزین HTTPS شود.

## ساخت حساب مدیر در اولین ورود

**هیچ حساب یا رمز مدیرِ پیش‌فرضی ساخته نمی‌شود.**

1. در خروجی نصب، مقدار `INITIAL_SETUP_CODE` را پیدا کنید.
2. پنل را باز کنید؛ صفحهٔ «ایجاد حساب مدیر» ظاهر می‌شود.
3. **نام کاربری دلخواه، رمز عبور، تکرار رمز و کد راه‌اندازی** را وارد کنید.
4. پس از ثبت موفق، ورودهای بعدی با همان نام کاربری و رمز انجام می‌شوند.

اگر خروجی نصب را از دست دادید، کد فقط از طریق دسترسی مدیریتی به سرور قابل مشاهده است:

```bash
sudo grep '^SETUP_TOKEN=' /opt/markaz/.env
```

این کد و فایل `.env` را در GitHub، اسکرین‌شات، پیام عمومی یا گزارش خطا منتشر نکنید. ساخت حساب اولیه پس از ایجاد مدیر دیگر فعال نخواهد بود.

## تنظیم ارزها و API نرخ

در بخش مالی می‌توان ارز یا دارایی جدید تعریف کرد و **نام، کد، نماد نمایشی، واحد و نرخ به تومان** را تغییر داد؛ برای مثال `USD` با `$`، `EUR` با `€`، `USDT` با `₮` یا یک دارایی سفارشی.

ارزش دارایی = **مقدار × نرخ هر واحد به تومان**.

در «تنظیمات و پشتیبان» یکی از منابع دریافت نرخ را انتخاب کنید:

- **NerkhAra / نرخ‌آرا (پیش‌فرض):** رایگان و بدون API Key؛ نرخ‌های دلار، یورو، تتر، طلای ۱۸ و ۲۴ عیار، سکه و رمزارزها؛ بازهٔ پیش‌فرض ۱۵ دقیقه؛ `IRT` به معنی **تومان** است و تقسیم بر ۱۰ نمی‌شود. [مستندات رسمی](https://nerkhara.com/en/api/).
- **ارزدیجیتال:** اتصال رسمی نسخهٔ قبلی حفظ شده است؛ پس از واردکردن کلید و قرارداد API می‌توان آن را به‌عنوان منبع فعال انتخاب کرد.
- **نوسان:** اتصال دارای API Key نسخهٔ قبلی حفظ شده است. در صورت دریافت نرخ ریالی، تبدیل به تومان انجام می‌شود.

در بخش «مالی → ارزها و نمادها» شناسه نرخ‌آرا برای هر دارایی اختیاری و قابل ویرایش است؛ در کنار قیمت‌های برگشتی، نام منبع و زمان نرخ نمایش داده می‌شود. نرخ‌های منقضی‌شده یا نامعتبر جایگزین قیمت موجود نمی‌شوند. منبع داده: [NerkhAra](https://nerkhara.com/).

راهنمای اختصاصی این نسخه: [NERKHARA-SETUP-fa.md](./NERKHARA-SETUP-fa.md).

## پایش سرورها

مقدارهای CPU، RAM و دیسک یا به‌صورت دستی ثبت می‌شوند یا از **عامل پایش (monitoring agent)** دریافت می‌شوند. برای استفاده از عامل باید هاست آن را در فهرست مجاز `ALLOWED_AGENT_HOSTS` تعریف و ارتباط امن و توکن احراز هویت را تنظیم کنید. مقادیر ثبت‌شدهٔ دستی را با دادهٔ زنده اشتباه نگیرید.

## مدیریت، به‌روزرسانی و پشتیبان

مشاهدهٔ سرویس‌ها و لاگ برنامه:

```bash
cd /opt/markaz
docker compose ps
docker compose logs --tail=100 app
```

به‌روزرسانی کد و ساخت مجدد سرویس‌ها (پس از گرفتن پشتیبان و بررسی تغییرات نسخه):

```bash
cd /opt/markaz
sudo git pull --ff-only
sudo docker compose --profile https up -d --build
```

> دستور بالا مخصوص نصب دارای دامنه و سرویس HTTPS است. برای نصب بدون دامنه، به‌جای سطر آخر از `sudo docker compose up -d --build` استفاده کنید.

پشتیبان کامل پایگاه‌داده:

```bash
cd /opt/markaz
sudo bash backup-db.sh
```

فایل پشتیبان در مسیر `backups/` ساخته می‌شود. آن را خارج از سرور و به‌صورت رمزگذاری‌شده نگهداری کنید. **پشتیبان JSON داخل پنل جایگزین پشتیبان کامل SQL نیست.** برای بازیابی کلیدهای API رمزگذاری‌شده ممکن است به `DATA_ENCRYPTION_KEY` همان نصب نیاز باشد؛ این مقدار را در محلی امن و جداگانه نگهداری کنید.

**هشدار:** از اجرای `docker compose down -v` بدون آگاهی از پیامد آن خودداری کنید؛ حذف volume می‌تواند اطلاعات PostgreSQL را از بین ببرد.

## اجرای توسعه‌ای و تست

پیش‌نیاز: Node.js 22، npm و Docker Compose. ابتدا نسخهٔ محلی `.env` را با مقادیر امن تکمیل کنید.

```bash
cp .env.example .env
# مقادیر محرمانهٔ .env را تنظیم کنید.
docker compose up -d --build db app
npm install
npm run dev
```

تست‌های موجود در پروژه:

```bash
npm test
npm run check
npm run secrets:scan
npm run build
npm audit --audit-level=high
```

این دستورات باید در محیط دارای دسترسی به npm و با نصب موفق وابستگی‌ها اجرا شوند. نتیجهٔ موفق تست واحد به‌تنهایی به‌معنای تأیید امنیت عملیاتی نیست.

## امنیت و محدودیت‌های فعلی

- فایل‌های `.env`، رمزها، توکن‌ها، بکاپ پایگاه‌داده و کلیدهای واقعی را **هرگز commit نکنید**.
- PostgreSQL نباید پورت عمومی داشته باشد. دسترسی مدیریتی به سرور و Docker باید محدود باشد.
- برای دسترسی از اینترنت، از HTTPS و رمز مدیر قوی استفاده کنید.
- نسخهٔ تحویلی گردش‌کار `.github/workflows/security.yml` دارد؛ برای استقرار بازتولیدپذیر، `package-lock.json` را با `npm install` بسازید و در مخزن commit کنید.
- اجرای واقعی `npm audit`، ساخت production، مهاجرت PostgreSQL و تست HTTPS روی VPS هنوز باید بررسی شود.
- انتشار عمومی مخزن به‌معنای تأیید امنیتی محصول نیست؛ قبل از استفاده برای اطلاعات حساس، تنظیمات و تاریخچهٔ Git را از نظر نشت اسرار ممیزی کنید.
